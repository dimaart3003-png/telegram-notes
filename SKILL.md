# Заметки из Telegram-бота

## Описание

Скрипт `check_notes.py` забирает новые сообщения из Telegram-бота через Bot API (`getUpdates`) и раскладывает их по двум файлам. Голосовые сообщения скачиваются через `getFile`, сохраняются в папку `voices/` и распознаются локально через Whisper (модель `base`, см. `WHISPER_MODEL_NAME` в скрипте). Записи в `voices/` старше 30 дней (`VOICE_MAX_AGE_DAYS`) автоматически удаляются при каждом запуске скрипта.

- `Idea.txt` — идеи
- `Zadacha.txt` — задачи

Каждая запись сохраняется в формате `[YYYY-MM-DD HH:MM] текст сообщения`.

Классификация — по ключевым словам-глаголам действия (см. `TASK_KEYWORDS` в `check_notes.py`): если в сообщении есть слово вроде «сделать», «купить», «позвонить», «поиграть» и т.п. — это задача, иначе — идея.

Скрипт хранит offset последнего обработанного сообщения в `state.json`, поэтому при повторном запуске обрабатывает только новые сообщения, а не всю историю заново.

## Как использовать

Пользователь просит проверить бота на новые сообщения/идеи/задачи, либо спрашивает, что нового поступило.

## Что делать

1. **Перейти в директорию скилла** (там же, где лежит этот SKILL.md) — там находятся `check_notes.py`, `.env` и `state.json`.

2. **Убедиться, что есть `.env` с токеном бота**:
   ```
   TELEGRAM_BOT_TOKEN=<токен от BotFather>
   ```
   Этот файл не хранится в git (см. `.gitignore`). Если файла нет — спросить у пользователя токен бота.

3. **Запустить проверку** (обязательно через venv — там установлены whisper/ffmpeg-зависимости):
   ```
   .venv/bin/python check_notes.py
   ```
   - При первом запуске (нет `state.json`) обрабатываются все сообщения, доступные через `getUpdates` (Telegram хранит неподтверждённую очередь максимум ~24 часа).
   - При последующих запусках — только сообщения, пришедшие после предыдущей проверки.

4. **Показать пользователю новые записи** — что добавилось в `Idea.txt` и что в `Zadacha.txt`, с датами. Если скрипт написал «Новых сообщений нет» — сообщить об этом.

## Замечания

- Telegram Bot API не хранит историю переписки: после того как обновление подтверждено (offset сдвинут), оно удаляется из очереди навсегда и повторно через API недоступно. Поэтому файлы `Idea.txt`/`Zadacha.txt` — единственный источник истории заметок, начиная с момента первой проверки.
- `.env` (токен), `state.json` (offset) и `voices/` (аудиозаписи) не должны попадать в публичный репозиторий — они уже в `.gitignore`.
- Оригинальные голосовые лежат в `voices/<дата>_<update_id>.oga` — можно переслушать или заново распознать другой моделью. Хранятся 30 дней, затем удаляются автоматически.
- Классификация по ключевым словам не идеальна: если сообщение с явным действием (например, с разговорным глаголом типа «зарубиться», «сгонять») попало не в ту категорию — можно расширить список `TASK_KEYWORDS` в `check_notes.py` и вручную перенести запись между файлами.
